# 交易日誌 & 情緒評分標準（20260706 建立）

> 本檔案記錄「使用者實際下單」的交易日誌機制，與 `daily/YYYY-MM-DD.json`（Claude的
> 每日分析建議）完全分開——daily json 是「分析當下我建議什麼」，這裡是「使用者實際
> 做了什麼、當下情緒狀態如何」。兩者可能有落差（例如進場時間、進場價與分析訊號不完全
> 一致），這是正常的，交易日誌**如實記錄使用者回報的內容**，不強行對齊分析紀錄。

---

## 一、情緒評分標準（1-5分，使用者提供，20260706確立）

每次使用者回報進場/停利/停損時，都要套用這套標準幫忙評分記錄。評分依據使用者當下
自述的心理狀態與行為特徵判斷，若使用者沒有主動描述，可以詢問或依對話上下文推斷，
但**評分理由要寫清楚依據什麼判斷**，不得憑空給分。

| 分數 | 定義 | 行為特徵 |
|---|---|---|
| **5** | 完全冷靜 | 訊號→對照SOP→下單，像做檢查表，有問過「有什麼理由拒絕這單」 |
| **4** | 冷靜但有期待 | SOP走完，但心裡有「這單應該會贏」的期待感 |
| **3** | 中性偏躁（警戒線） | 有按SOP但當下急躁、怕錯過，或前一筆情緒還沒歸零 |
| **2** | 明顯情緒驅動 | 「覺得」大於訊號、連虧想扳回、大賺覺得手感來了、SOP跳步驟 |
| **1** | 完全情緒 | FOMO/報復、沒訊號硬進、追高殺低、事後說不出進場理由 |

**3分是警戒線**：3分以下（3/2/1）建議在日誌備註中額外提醒使用者留意，未來累積數據
如果發現特定盤別/策略/連續交易情境下情緒分數持續偏低，應該在分析時主動提出觀察。

## 一之二、使用者進場回報固定格式 + H2雙倉預設SOP（20260706新增）

**使用者進場回報格式**：使用者進場時只需告知「策略、點位、情緒、原因」四項，不需要
每次都報SL/TP數字。

**H2雙倉預設規則（使用者實際交易SOP，非僅分析建議）**：若使用者進場時沒有特別說明
SL/TP，一律預設套用「H2」結構：
- **Lot1**：在 1R 出場，落袋為安
- **Lot2**：Lot1出場後SL移到保本，讓利潤繼續跑到 2R

這與 ANALYSIS_SKILL.md 分析建議裡的「H2雙倉鐵律」是同一套邏輯，但這裡是使用者
**明確表示自己實際下單就是照這個規則做**，所以trade_journal記錄SL/TP時，若使用者
沒特別提供實際數字，就記錄「採用H2預設（Lot1 TP1=1R拿利潤，Lot2 SL移保本後跑2R）」
這句話，而不是留空或亂猜一個數字；若使用者之後有回報實際下的SL/TP數字，以使用者
說的實際數字為準，取代預設描述。

## 二、交易日誌檔案機制

**檔案路徑**：`/Users/tittan/googledrive/Github/trading/xauusd/claude/trade_journal/{年份}-W{週次}.json`
（例如本週：`trade_journal/2026-W28.json`），依ISO週次分檔，一週一個檔案，JSON array，
新記錄append在最後。

**單筆記錄 Schema（扁平化，風格比照 daily json v1.0）：**

```json
{
  "schema_version": "1.1",
  "timestamp": "2026-07-06T07:00:00+08:00",
  "week": "W28",
  "session": "亞盤/歐盤/美盤",
  "direction": "long/short",
  "strategy": "S1/S2",
  "strategy_version": "v3.7",
  "entry": 4189,
  "sl": null,
  "tp1": null,
  "tp2": null,
  "status": "open/closed",
  "exit_price": null,
  "exit_timestamp": null,
  "pnl": null,
  "emotion_score": 4,
  "emotion_label": "冷靜但有期待：SOP走完，但心裡有「這單應該會贏」的期待感",
  "user_note": "使用者自己的原話備註，逐字記錄",
  "trade_note": "額外備註，例如版本標記、與分析訊號的落差說明",
  "related_signal_ref": "可選，若能對應到某次daily分析的訊號，簡短標註方便交叉查閱，但不強行對齊時間/價格",
  "scenario_context": "進場當下對應本週週報的哪個劇本，例如「劇本一」",
  "scenario_probability": 57.5,
  "aligned_with_weekly_report": "順勢/逆勢/中性"
}
```

**欄位說明重點**：
- `timestamp`／`entry`：一律照使用者回報的原始數字記錄，即使跟同時段daily json的
  分析訊號時間/價格有落差，也不強行修改對齊，落差可以寫在`related_signal_ref`裡
  當作備註，但主欄位保留使用者原話。
- `emotion_score`＋`emotion_label`：兩個一起存，分數對照的定義文字每次都完整帶入，
  避免以後只看到數字忘記當初對照的行為特徵。
- `sl`/`tp1`/`tp2`：使用者進場只報「策略、點位、情緒、原因」、沒特別說SL/TP時，
  一律記錄為採用「H2預設」（見上方一之二節：Lot1 TP1=1R拿利潤，Lot2 SL移保本後
  跑2R），不留空、不亂猜數字；若使用者之後回報實際下的數字，才用實際數字取代。
- `exit_price`/`pnl`：使用者沒提供就留null，之後回報停利/停損時再更新同一筆記錄
  （或append一筆對應的出場記錄，視情況決定）。
- `status`：open（尚未出場）/ closed（已出場，此時應補上exit_price/exit_timestamp/pnl）
- `scenario_context`／`scenario_probability`（20260706新增）：這筆交易進場當下，
  對應本週週報／Combine的哪個劇本、當時給的機率是多少，方便之後回顧交易跟週報
  劇本的對應關係
- `aligned_with_weekly_report`（20260706新增）：這筆交易方向是否符合週報當下的
  主要偏向——`順勢`＝跟隨週報主劇本方向、`逆勢`＝跟週報主要偏向對做、`中性`＝
  週報本身方向不明確或此為區間操作，用來回顧「是不是常常在跟週報對做」

**使用時機**：使用者主動跟Claude報告「我進場了」「我出場了」「停利/停損了」時觸發，
不是「請分析」流程的一部分，是獨立的日誌記錄動作。

## 三、與 daily json / ANALYSIS_SKILL.md 的關係（20260706 更新：已正式串接）

- `daily/YYYY-MM-DD.json`：Claude每次分析的建議與市場讀值（Step 6 定義）
- `trade_journal/{年份}-W{週次}.json`：使用者實際下單行為 + 情緒評分（本檔案定義）

**20260706 起，`ANALYSIS_SKILL.md` 的 Step 1 已正式加入讀取本機制的規則**：每次
「請分析」讀完context.md後，一併讀取本週`trade_journal/{週次}.json`，篩出
`status:"open"`的記錄，若有未平倉部位，在③當前位置或💡建議段落提示「目前持倉」。

**主從關係規則（重要）**：`trade_journal`是使用者實際部位的**唯一真相來源**，
`context.md`「當前狀態」的倉位欄位只是鏡射顯示。若兩者不一致（例如trade_journal
顯示open但context.md寫空手），分析時要明確提醒使用者「context.md倉位欄位需要
更新」，不得自己選一邊當作正確答案就跳過提醒。
